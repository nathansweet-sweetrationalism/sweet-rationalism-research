# Mandatory verification of article mathematics, code and agent instructions

Version 1 | 2026-11-11 | Mandatory for **every independent coding agent** working on WordPress article #218725796.

## Principle and limits

Audit **every material mathematical, statistical, numerical, algorithmic, model-comparison and formal logical claim** in the actual current article, as well as every runnable script, package, command and all **14 expandable agent-instruction panels**. The aim is maximum discriminating reliability under practical compute limits, **not** running every tool indiscriminately. There is no single "best" mathematical tool for all fields. Choose a current, independently downloadable, inspectable, well-maintained tool whose formal semantics, numerical capabilities and evidence type fit each specific claim. Record why it is adequate and what it cannot establish. A proof checker does not verify biological premises; a statistical package does not establish a nonphysical ontology; a source-string match is not a numerical replication.

Do not let a language model silently assert an equation is correct, a paper is peer reviewed, a proof is complete, or a script ran. Use deterministic retrieval, parsers, formal proof checkers, independent calculations and negative controls. Scope reports to what those procedures actually establish.

## Peer-reviewed and authoritative method sources, correctly scoped

- Sandve, Nekrutenko, Taylor & Hovig (2013), *Ten Simple Rules for Reproducible Computational Research*, **PLOS Computational Biology**, https://doi.org/10.1371/journal.pcbi.1003285. Apply preservation of inputs/outputs, recorded versions, workflows, exact transformations and reproducible results.
- Wilson et al. (2017), *Good enough practices in scientific computing*, **PLOS Computational Biology**, https://doi.org/10.1371/journal.pcbi.1005510. Apply versioned scripts, file/data organization, dependency tracking, source preservation and collaboration practices.
- Oberkampf & Trucano (2002), *Verification and validation in computational fluid dynamics*, **Progress in Aerospace Sciences**, https://doi.org/10.1016/S0376-0421(02)00005-2. Apply distinctions between code verification, numerical solution verification, model validation, predictive adequacy and uncertainty **when simulations/numerical models warrant them**; do not claim this CFD review is a universal mathematics standard.
- Wasserstein & Lazar (2016), *The ASA Statement on p-Values: Context, Process, and Purpose*, **The American Statistician**, https://doi.org/10.1080/00031305.2016.1154108. Apply to inferential statistics: avoid treating a p-value as a hypothesis probability; inspect selection, effect size, uncertainty and assumptions.
- Percie du Sert et al. (2020), *The ARRIVE guidelines 2.0*, **PLOS Biology**, https://doi.org/10.1371/journal.pbio.3000410. Apply its reporting criteria when evaluating **original in vivo animal experiments**, not as an irrelevant requirement on an article's philosophical arguments.
- For formal checker guarantees, consult official documentation rather than treating tooling descriptions as peer-reviewed results: [Lean language reference](https://lean-lang.org/doc/reference/latest/), [Isabelle](https://isabelle.in.tum.de/), [cvc5](https://cvc5.github.io/), [Z3](https://github.com/Z3Prover/z3). Check exact versions, supported logics and solver proof-output limitations.

The named papers are methodological guidance. They do not independently validate this article, its claims or any agent's output. Search and apply an additional **claim-specific peer-reviewed methodological source or reporting guideline** when the material involves a field not covered above. Cite the actual passage and explain why that method applies; use the strongest fit, not indiscriminate citations.

## Choose and install tools by proof obligation, not popularity

| Claim or task | Strong available, downloadable tools to evaluate | Proof burden and independently checked failure modes |
| --- | --- | --- |
| Elementary and exact arithmetic; score means, ranges, denominators, Bayes-factor algebra | Python `fractions.Fraction` / `decimal.Decimal`, R, SymPy, SageMath; cross-check with a separately written implementation | Exact data transcription, formula, rounding, dropped rows, weighting, denominator, edge cases; a score average is not a posterior probability |
| General symbolic algebra, identities, equations | SymPy / SageMath / Mathematica as accessible, then independent algebra or rational counterexamples | Domains, branches, singularities, complex/real/positive restrictions, hidden division by zero |
| Universal formal theorem/proof | Lean 4 + pinned mathlib, Isabelle/HOL or Rocq (Coq), when feasible and expressively appropriate | No `sorry`, untrusted axioms, admission, opaque oracle or incomplete sketch. Keep checked theorem statement, dependencies, kernel result and human-verified translation; if infeasible, **proof incomplete** |
| Propositional/SMT constraints and bounded models | cvc5 and Z3 in supported fragments; optional independently verified SAT encoding or enumerator | Explicit quantified premises/axioms, model semantics, assumptions, satisfiability of premises AND negated conclusion, solver versions, countermodel; UNSAT proves only the encoding, solver/proof trust matters |
| Numerical methods, ODEs, optimization and simulation | NumPy/SciPy, Julia DifferentialEquations.jl, R, mpmath/interval arithmetic, independently implemented reference as warranted | Units, tolerances, convergence, time step, initial/boundary conditions, numerical stability, target supplied as input, grid/angle convention, sensitivity, false apparent optimum and uncertainty |
| Statistics, claimed p-values/CI/Bayes factors | R with relevant packages or Python scipy/statsmodels/PyMC (only when model defined), independent alternate package/formulation | Raw data, study design, test assumptions, selection, comparison baseline, effect size, interval, multiplicity, prior/likelihood specification, nonindependence, rounding and power |
| General scripts, packages and every displayed command | `python -m compileall`, `pytest`, `hypothesis` if appropriate, static AST analysis, `ruff`/type checks, shell syntax checks, package locks, SHA-256, ZIP validation | Real exits, stdout/stderr, safe extraction, version compat, dependencies, offline-vs-live mode, network error handling, actual conditional verdict logic, negative/positive controls |
| Biological interpretation of models and figures | Primary papers' methods, supplements, raw data, exact statistical scripts; ARRIVE for original animal experiments where applicable | Separate observed experiment, reduced simulation, programmed target, explanatory analogy and metaphysical inference; source provenance and experimental controls |

**Installation discipline:** Prefer official releases, trusted package managers and pinning of versions/dependency hashes where feasible; run in a clean isolated workspace. Inspect code, licenses and possible external side effects before execution. Prefer standard-library or already available deterministic tools when sufficient. Install additional tools only if they materially reduce an uncertainty. Report inaccessible, unsupported or uninstalled tools; never pretend a proof assistant was used when it was not. For consequential universal results, use kernel-checked proofs where tractable and an independent checker/countermodel search; for numerical results, independent implementations and convergence/sensitivity where meaningful.

## Mathematical audit receipt for EVERY material claim

For each claim, save in the private ledger and the redacted public result:
- `claim_id`, complete coverage pointers (WordPress section/block IDs, no unreleased verbatim text in public), original-source URL and immutable hash, and classification (exact arithmetic | theorem | statistical estimate | numerical solution | causal inference | simulation | philosophical assertion).
- Definitions, formal statement, types, units, quantifiers, domain, boundary, time scale, assumptions, data inputs, expected outputs and what would contradict it.
- Suitable **primary mathematical/technical sources** and peer-reviewed claim-specific methods with DOI/passage where available. Identify which guidelines apply and which do not.
- Chosen tool and why, version, source/download provenance, environment, commands, raw outputs, seed, precision, tolerances, inputs and SHA-256, exact tested cases.
- Independent cross-check (different implementation or different proof mechanism), positive and negative controls, adversarial edge cases and counterexample search; justify infeasibility.
- Test result `proved by a complete derivation` | `kernel-checked under specified assumptions` | `SMT unsatisfiable under encoding` | `bounded tests passed` | `counterexample` | `proof incomplete` | `empirical bridge unverified` | `NOT_RUN`, plus a **separate** empirical/source result. A numerical agreement cannot upgrade an ontological claim.
- Serious rival, precise remaining uncertainty, falsification or support-loss condition, smallest defensible correction and whether the correction alters the argument.

For every article section containing math, state how many unique mathematical claims were inventoried and how many verified, partially tested, refuted, or unresolved. Do not infer zero mathematical claims merely because none are typeset in LaTeX. A linearly combined score, a Gaussian peak, a percentage and a causal comparison also count.

## Test every agent prompt, not merely its premise

For **each of the 14 panel occurrences**, require source and rendered location, the exact referenced GitHub and WordPress ZIPs, downloaded SHA-256, ZIP listing/CRC, README / PROMPT / `test.json` / `audit.py` identity, command syntax, exit code, stdout/stderr and behavior on missing or malformed inputs. Independently verify that all required URLs are accessible or correctly fail and that the prompts' **instructions match actual executable CLI flags**. The correct per-package local invocation is `python audit.py --live` and `python audit.py --selftest`; the shared repository config path form is `python audit.py --live --config test-data/<test-id>.json`. An offline fixture check must never be described as a live replication. Test that the promised status labels agree with the code (for example, `SELFTEST_ONLY` versus a prose label of `FIXTURE_CHECK_ONLY`). Test copy/expand interaction in a browser if available, no spurious external execution, and HTML escaping so users really receive the intended prompt bytes.

Run **one initial inventory, then batch pure checks over all panels and packages**. Group repeated content by SHA-256 and run the unique executable code only once *when inputs and versions are truly identical*, while still auditing each panel's location/links/copy and reporting its unique ID. Stream only failing or ambiguous snippets to the language model. Do not reprint 14 long prompts, seven ZIP contents or every passing log. Store full logs as files, produce terse JSON/CSV receipts and exception-first summary. Cache immutable source downloads by URL + commit + SHA-256, without claiming cache copies are new independent evidence.

## Meaningful, bounded improvements

Propose an edit only if a concrete failing test, contradiction, reproducibility gap, technical security issue, misleading status, or demonstrably better readability/transfer motivates it. Use explicit before/after assertions or measured checks. Include the **smallest safe patch** and test that the relevant result improves with no loss of claims, original quotations, provenance, accessibility, privacy or other working tests. Avoid cosmetic edits, claim-softening without evidence, new jargon, unearned philosophical changes or additional Git commits for routine WordPress presentation.

Maintain all draft content privately. Public pull requests contain only scripts, redacted receipts, stable public-source URLs, independently reproducible test data, tool versions and hashes. The central release-status document is coordinator-only. Independently submitted reports can be accepted into the final combined computational-audit ZIP **after verification and owner-approved release**.
